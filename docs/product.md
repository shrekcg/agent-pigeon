# 产品介绍

## 一句话

Agent 信鸽（Agent Pigeon）把电脑上 AI Agent 的会话接进消息软件：一个会话对应一个话题，在手机上就能接着推进。

## 要解决的问题

现在 AI Agent（Claude Code、Codex、Grok 等）都跑在电脑上，任务一跑就是十几分钟甚至更久。人一离开电脑，就会遇到这些问题：

- 不知道任务跑完没有、卡没卡住；
- 想补一句需求、纠正方向，只能回到电脑前；
- 好几个 Agent、好几个会话同时在跑，开远程桌面又太重；
- 各家 Agent 自带的远程功能（如果有）各不相同，一次往往只能连一个会话。

信鸽的做法：把每个会话变成飞书里的一个话题，用户在话题里说话，消息就送进那个会话；Agent 的进度和结论实时回到话题里。

## 目标用户

- 在本机同时用多个 AI Agent 写代码、做研究、处理杂务的个人开发者和产品经理；
- 日常主要用飞书沟通的人（后续扩展到钉钉、QQ、微信）。

## 核心场景

1. **离开电脑后接着干**：出门前在 Agent 里说一句「把这个对话接入飞书」，之后在手机上追问、补需求、看结果。
2. **多个 Agent 并行**：每个会话一个话题，标题带来源（`[Codex] 修复 CI`），互不串台。
3. **从飞书直接开任务**：`/ht@claude〈写周报〉` 会在本机新建一个 Claude 会话，并为它开一个话题。
4. **盯长任务、远程干预**：流式卡片显示进度和工具步骤；可以点「停止」、插话、排队；遇到需要审批的工具调用，直接在卡片上处理（支持审批的 Agent）。
5. **收发文件**：飞书里的图片和文件交给 Agent；Agent 本轮产出的文件自动回传到话题。

## 功能清单

| 能力 | 说明 |
| --- | --- |
| 一会话一话题 | 话题名片首行是 `[Agent] 标题`；名片上写着会话 ID、模型和目录 |
| 不隔离模式 | 所有会话进同一个对话，消息带会话名；回复哪条就发给哪个会话，`/ht-use` 可以切换 |
| 双向消息 | 话题里的消息进会话；会话的输出以流式过程卡和结论卡回到话题 |
| 插话与排队 | 运行中默认插话（Agent 支持时），否则自动排队；`/pd` 强制排队；发「停」中断 |
| 远程审批 | 卡片按钮或表情回应（PenguinHarness、Hermes） |
| 媒体 | 收图片和文件（存到本地后交给 Agent）；回传本轮产出的文件（最多 5 个） |
| 从 Agent 侧接入 | 每个 Agent 装一个 `feishu-topic` Skill，一句话接入当前会话 |
| 从渠道侧操作 | `/ht` 指令族：新建、接入、列表、改名、下线、切换 |
| 会话巡检 | 支持的 Agent 的会话被归档或删除后，对应话题会自动下线 |
| 本地控制台 | 概览、渠道、Agent、会话、设置五个页面；可以暂停转发、安装 Skill、下线会话 |

## 不做什么

- **不调用模型**：信鸽只转发消息，不产生任何模型费用。
- **不替代 Agent 的界面**：会话的完整历史仍在 Agent 自己那里，信鸽不补发旧消息。
- **不做多人协作**：一个机器人对应一个用户的单聊，不是群机器人。
- **不做云端托管**：所有东西都跑在用户自己的 Mac 上。

## 与同类方案的区别

| 方案 | 区别 |
| --- | --- |
| 各 Agent 自带的远程控制 | 通常一次只能绑一个会话，只有聊天流；信鸽支持多个会话、多个 Agent、审批和媒体 |
| 远程桌面 / 屏幕共享 | 在手机上操作太重；信鸽只传对话 |
| Magpie 这类网关 | Magpie 管的是「Agent 用哪个模型」，信鸽管的是「Agent 的对话送到哪」，两者可以同时使用 |

## 命名

英文名 Agent Pigeon，中文名 Agent 信鸽。取「信鸽」送达的意思：把各个 Agent 的消息送到各个通知渠道，重点是通知和送达。
